# Endpoint guide

All routes are defined in `app/main.py` and exposed in Swagger at `/docs`. MongoDB stores attendance records in `attendance_logs` and employee details in `employees`.

## System

### `GET /health`

Pings MongoDB and returns `{ "status": "ok" }` when the database is available. It returns `503` when MongoDB cannot be reached. This prevents the service from being reported ready before its dependency is ready.

## Employees

### `POST /employees`

Creates an employee. The request supplies `emp_code`, name, email, department, shift times, and joining date. The API validates formats and rejects equal shift boundaries. `created_at` is generated by the server. A unique MongoDB index makes concurrent duplicate codes return `409`.

### `GET /employees`

Lists employees sorted by `emp_code`. It supports an exact department filter and page-based pagination. The total is calculated from the same filter as the page query.

## Attendance

### `POST /attendance/punch-in`

Creates one attendance record for an employee and attendance date. Timestamps are strict integer epoch milliseconds, truncated to whole seconds, and interpreted in IST. The endpoint calculates the attendance date, including overnight shifts, and stores `late_minutes`. Only `PRESENT`, `WFH`, and `ON_DUTY` are accepted. The unique `(emp_code, date)` index makes simultaneous punch-ins safe.

### `GET /attendance`

Lists attendance records sorted by date descending and employee code ascending. It supports employee, inclusive date-range, and status filters. Sorting, skipping, limiting, and counting are performed by MongoDB rather than loading the collection into Python.

### `POST /attendance/punch-out`

Finds the employee’s latest open punch-in at or before the requested timestamp. It rejects timestamps before punch-in or more than 24 hours later. An atomic update calculates and stores `work_hours`, `overtime_minutes`, and `half_day`. A second simultaneous punch-out receives `409`.

### `PATCH /attendance/{emp_code}/{date}`

Regularizes one existing attendance record. It accepts status, punch-in, and punch-out changes, validates the final state, recomputes all derived fields, and appends one audit entry containing only changed fields. Concurrent edits are detected so one update cannot silently overwrite another history entry.

## Analytics

### `GET /analytics/employees/{emp_code}/monthly`

Aggregates one employee’s stored attendance values for a calendar month. It reports working days, present days, leave days, late counts, late minutes, overtime, and attendance percentage. Weekdays are counted from `joined_on`, and half days count as `0.5`.

### `GET /analytics/departments/summary`

Summarizes departments for a month. Employees are selected from the employee collection first, so employees with no logs still contribute to headcount. Log metrics are then joined by `emp_code`. Optional department filtering is supported.

### `GET /analytics/leaderboard/late`

Ranks employees by stored total late minutes. It joins names and departments from `employees`, supports a department filter, and uses standard competition ranking: `1, 2, 2, 4`. The limit is applied after ranking, so ties at the cutoff are retained.

### `GET /analytics/departments/{department}/trend`

Returns one row for every requested calendar day, including weekends and empty days. It reports headcount, present count, late count, attendance rate, and a seven-day moving average. The range is limited to 92 days.

## Explain

### `GET /admin/explain/{endpoint}`

Returns MongoDB `executionStats` explain output for the named operation: `attendance_list`, `employee_monthly`, `department_summary`, `late_leaderboard`, or `department_trend`. It accepts the relevant endpoint parameters and is used to verify index scans and avoid collection scans.

## Common conventions

- API instants are integer epoch milliseconds; MongoDB stores them as BSON UTC datetimes.
- Calendar dates are `YYYY-MM-DD`; months are `YYYY-MM`; shift times are `HH:MM` in IST.
- MongoDB `_id` values are internal and never returned by the API.
- Derived fields are computed by the API and analytics read the stored values.
